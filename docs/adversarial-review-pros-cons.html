Pros and cons

Standard run

Folder: 20261021-1029_test_feat-adversarial-agents-cmp-std

Pros

  • Independent verification. A fresh agent traced every finding in the code and confirmed all 7. None was refuted or left unclear.
  • Well-evidenced findings across testgen, core and functest, each with file and line.
  • Extra detail from Pass 3, such as the registry URL gets a trailing-slash strip but the emitted tests' base URLs do not.
  • Faster overall, and fewer unverifiable citations.
  • Full accounting of the 66 blind items, with reasons for the 7 uncovered.

Cons

  • No Major or Critical findings, so it may be less aggressive. "PASS WITH NOTES" could be too lenient.
  • Two findings (compat and conformance file collisions, UTF-16 ordering) describe catalog states that don't exist today and no test pins them.
  • Did not look at packages/adversary, where the other run found a confirmed Major.
  • Two separate agents mean two handoffs and more orchestration.

-update run

Folder: 20261021-1029_test_feat-adversarial-agents-cmp-upd

Pros

  • Found a confirmed Major the other run missed: mutate-testgen.ts:71 treats "no logicalType on either side" as green, while the emitted test fails (R-84a), so the tiers disagree and the CLI aborts.
  • Wider coverage: included packages/adversary, plus a digit-leading env-var syntax error and a hard-coded report tier.
  • Refuted its own finding (F-03) and admitted one piece of evidence was overstated.
  • More judgement calls surfaced: 9 decision items, including four critic findings it disagrees with and a possible missing validity filter in functional-gen.ts.
  • One agent instead of two.

Cons

  • Only 3 of 7 findings are firmly confirmed. 3 are unclear and 1 is refuted.
  • Verdict inflated: finalize counts the refuted Major, so 2 of the 4 Majors are refuted or unclear. FAIL still holds because F-02 is a confirmed Major.
  • Three Majors share one weak premise: a capitalised logicalType, which is ODCS-invalid and which testgen skips.
  • Self-verification: the agent checks its own findings, so confirmations are less independent.
  • Slowest: about 25 minutes in one agent.

Caveats

One run each. Agent differences cannot be separated from run-to-run variation. Two earlier UI runs on this branch gave 10 Minor, then 2 Major and 6 Minor, so the variation is large.
  • No live contracts: both runs used sources: none, so neither compared fields against live contract files.
  • No functional tests existed: plans: [], so the unmapped-path and absent-field checks had nothing to run on. Blind items X-19 to X-35 could only be judged against the generator code.
  • Blind pass miscount: it said 171 requirement ids, but the manifest has 168. Both runs flagged it.
  • Unreconciled overlap: the standard run's F-03 reports a bug in the emitted at(), while the -update run says the nullable exists behaviour follows R-117b. They concern different issues, but the two claims need reconciling.

Recommendation

  • Default to the standard chain. It is faster and its verdicts are better supported.
  • Use -update as a second opinion. It found a different set of Majors, but treat its findings as unverified until a separate Pass 3 checks them.
  • Check mutate-testgen.ts:71 by hand. It is the one confirmed Major, and only the -update run found it.
  • For a firmer answer, repeat each agent 2 to 3 times on the same snapshot and compare how much the findings overlap.
